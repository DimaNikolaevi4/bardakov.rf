# Аудит текущего сайта

## Назначение

Эта папка содержит рабочие материалы для решения задачи 1: аудита текущего сайта бардаков.рф перед переносом с Joomla на новую статическую платформу.

На этапе аудита мы фиксируем фактическое состояние сайта, структуру, URL, контент, технические зависимости, причины нагрузки и риски миграции. Код текущего сайта и production-настройки не изменяем.

## Источники аудита

### Основной источник

1. Живой сайт: https://бардаков.рф/

Живой сайт считается источником фактического поведения: доступности страниц, текущих URL, меню, контента, редиректов, ошибок, изображений и документов.

### Архив в репозитории

2. old/joomla/

Архив файлов Joomla, сохранённый в этом репозитории. Используется для анализа:

- .htaccess;
- robots.txt и sitemap.xml;
- пользовательских изображений и документов;
- папок files/, images/ и dok24/;
- подключённых кастомных файлов и следов Joomla-компонентов.

Важное ограничение: old/joomla/ не считается полной копией установленной Joomla. Согласно существующему old/joomla/.gitignore, стандартные папки ядра, временные каталоги и часть компонентов исключались из Git. Поэтому отсутствие файла в архиве не доказывает его отсутствие на рабочем сайте.

### Дополнительные источники

3. old/homepage/

Отдельный снимок главной страницы: index.html, style.css и scripts/. Используется как дополнительный материал для сравнения контента и визуального состояния главной страницы.

4. old/new-stack/

Предыдущая попытка статической версии сайта. Используется только как справочный материал для найденной структуры URL, перенесённых страниц и уже принятых решений. Не является источником истины для текущего сайта.

5. ../README.md и ../old/CHECKLIST.md

Контекст проекта и ранее составленные задачи. Не заменяют результаты текущего аудита.

6. ../old/new-stack/CHECKLIST.md

Справочный пример подробного чек-листа и ранее зафиксированных идей для статической версии.

## Правила фиксации результатов

- Для каждого вывода указывать источник: URL, путь к файлу или оба источника.
- Разделять подтверждённые факты, предположения и вопросы, требующие доступа к Beget или Joomla.
- Не считать неполный архив Joomla доказательством отсутствия функциональности.
- Не менять production-сайт во время аудита.
- Не удалять и не перезаписывать исходные материалы.
- Все спорные решения выносить в отдельный список вопросов перед этапом проектирования.

## Результаты аудита

Основной результат будет зафиксирован в CHECKLIST.md. После завершения там должны появиться:

- карта текущих разделов и URL;
- инвентаризация контента и файлов;
- список технических зависимостей Joomla;
- риски нагрузки, базовая точка сравнения и план контроля после миграции;
- список проблем, рисков и неизвестных;
- таблица соответствия старых и будущих URL;
- требования к новой статической версии;
- решение о готовности переходить к визуальной концепции и миграции.
