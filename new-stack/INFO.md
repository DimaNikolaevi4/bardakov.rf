# Информационный файл: Переход бардаков.рф с Joomla на современный стек

## 1. Текущее состояние

Сайт **бардаков.рф** работает на **Joomla 5** — классической CMS с серверным рендерингом, динамической базой данных (MySQL) и PHP. Управление контентом осуществляется через административную панель Joomla. Это стандартный подход, который обеспечивает простоту редактирования, но имеет ограничения по производительности, безопасности и современным практикам разработки.

## 2. Цель миграции

Перенести сайт на **современный статический стек** по аналогии с уже реализованным проектом https://github.com/DimaNikolaevi4/site (сайт Сальского индустриального техникума — сит-сальск.рф). Это позволит получить: быструю загрузку страниц, версионирование контента через Git, совместную работу разработчиков, отсутствие уязвимостей серверной CMS и простое развёртывание.

## 3. Референсный проект (сит-сальск.рф)

Проект `DimaNikolaevi4/site` представляет собой зеркальную копию сайта техникума, мигрированную с WordPress на статический генератор. Ниже — детальный разбор его стека и архитектуры.

### 3.2. Архитектура сайта

Сайт построен по принципу **8 фиксированных секций** и **3 типов страниц**:

**8 секций (канон):**
1. **Шапка** (`header.njk`) — логотип, навигация, контакты, поиск
2. **Hero** (`hero.njk`) — баннер с названием рубрики или материала
3. **Хлебные крошки** (`breadcrumbs.njk`) — навигационная цепочка
4. **About** (`about.njk`) — информационный блок (режимы: `home`, `razdel`)
5. **Материалы** (`news.njk`) — карточки материалов / подрубрик
6. **Популярное** (`popular.njk`) — 3 карточки популярных материалов
7. **Сайдбар** (`sidebar.njk`) — баннеры, 30% ширина слева
8. **Подвал** (`footer.njk`) — контакты, реквизиты, ссылки

**3 типа страниц:**
- **Тип A** — Главная (`index.njk`): все секции кроме хлебных крошек
- **Тип B** — Раздел (`page-full.njk`): все 8 секций, используется для 11+ разделов сайта
- **Тип C** — Материал (`post.njk`): шапка, hero, крошки + мета, контент, «Читайте также», подвал

### 3.3. Структура проекта

```
src/
├── _data/              # Глобальные данные (site.yaml, rubrics.yaml, menu, contacts, social)
├── _filters/           # Пользовательские фильтры Nunjucks (dateRu, slugify, truncate, lunr-index)
├── _includes/          # Шаблоны и компоненты
│   ├── base.njk        # Базовый макет (head, header, main, footer)
│   ├── components/     # 8 компонентов секций + _partials/ (card, pagination, share, related)
│   └── layouts/        # page.njk, page-full.njk, post.njk, listing.njk, svedenija-page.njk
├── admin/              # Decap CMS (index.html + config.yml)
├── assets/             # Статические файлы (JS, изображения, загрузки, фавиконы)
├── styles/             # main.css — единственный продакшен-CSS (~7300 строк)
├── content/            # Контент сайта в Markdown
│   ├── abiturientam/   # Разделы
│   ├── categories/     # Индексные страницы рубрик
│   ├── news/           # Новости
│   └── pages/          # Статические страницы и подразделы
├── pages/              # Шаблонные страницы (search, news-list и др.)
└── index.njk           # Главная страница
```

### 3.4. Ключевые решения из референса

1. **Единый CSS** — только `src/styles/main.css`, никаких SCSS-препроцессоров. Все правки стилей в одном файле.
2. **Данные в YAML** — рубрики, контакты, меню, социальные сети — всё в `src/_data/*.yaml`, не в БД.
3. **Контент в Markdown** — каждая статья/страница — `.md` файл с YAML front matter. Хранится в Git, версонируется.
4. **Поиск Lunr.js** — индекс генерируется при сборке, поиск работает на клиенте без сервера.
5. **Decap CMS** — контент-редакторы работают через веб-интерфейс `/admin/`, не трогая Git напрямую.
6. **Деплой через bash** — `deploy.sh` клонирует репо, собирает, копирует в `public_html` на Beget.

## 4. Что нужно адаптировать под бардаков.рф

### 4.1. Структура разделов

У бардаков.рф своя структура разделов, отличная от сайта техникума. Необходимо:
- Составить полный список разделов и подразделов сайта
- Определить тип страницы для каждого раздела (A, B или C)
- Создать `rubrics.yaml` с иерархией рубрик
- Спроектировать навигационное меню

### 4.2. Контент

- Экспорт контента из Joomla (статьи, категории, модули, меню)
- Конвертация в Markdown с сохранением форматирования
- Перенос изображений и вложений (PDF, DOC)
- Обработка внутренних ссылок

### 4.3. Функциональность

Определить, какие функции Joomla нужно заменить:
- **Формы обратной связи** → статический HTML + серверный обработчик (PHP или внешний сервис)
- **Галереи изображений** → GLightbox (уже в стеке)
- **Меню** → генерируется из `rubrics.yaml` при сборке
- **Поиск** → Lunr.js (уже в стеке)
- **Управление пользователями** → не нужно для публичного сайта
- **Комментарии** → внешний сервис (например, Cusdis или Giscus)

### 4.4. Дизайн

- Выбрать цветовую схему (Bootstrap-тему можно кастомизировать через CSS-переменные)
- Адаптировать компоненты под фирменный стиль бардаков.рф
- Сохранить или улучшить текущую навигацию

## 5. Преимущества перехода на новый стек

| Аспект | Joomla 5 | Eleventy + статика |
|--------|----------|-------------------|
| Скорость загрузки | 1-3 сек (динамический PHP) | 0.1-0.5 сек (статический HTML) |
| Безопасность | Уязвимости CMS, плагинов | Нет серверного кода = нет атак |
| Версионирование | Нет (БД) | Полное (Git) |
| Совместная работа | Через админку (по одному) | Через Git + Pull Request |
| Хостинг | PHP + MySQL (~300-500 руб/мес) | Статика (~100-200 руб/мес) |
| Масштабируемость | Ограничена сервером | CDN, любой трафик |
| Редактирование контента | Админка Joomla | Decap CMS или Git |

## 6. Риски и ограничения

1. **Динамический контент** — если на сайте есть пользовательские формы, авторизация, форум — их придётся решать отдельно (внешние сервисы или серверные API)
2. **Миграция контента** — ручная или полуавтоматическая конвертация большого объёма статей
3. **SEO-переезд** — необходимо настроить 301-редиректы со старых URL на новые
4. **Обучение команды** — контент-редакторам нужно привыкнуть к Decap CMS вместо Joomla
