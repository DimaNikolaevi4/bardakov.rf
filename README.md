# Новый сайт бардаков.рф

## Цель проекта

Переделать сайт https://бардаков.рф/ с Joomla на лёгкую, быструю и поддерживаемую статическую платформу.

Новый сайт должен сохранять полезный контент и структуру текущего ресурса, но не создавать неконтролируемую нагрузку на хостинг. Контент должен быть отделён от шаблонов, чтобы новые страницы и материалы можно было добавлять через GitHub и в будущем поручать ИИ-агенту по описанному шаблону.

## Исходные условия

- Текущий сайт работает на Joomla.
- В меню 5 главных разделов.
- В каждом главном разделе примерно 4–5 подразделов.
- Контент обновляется редко — ориентировочно один раз в месяц.
- Обычная посещаемость — до 50 человек в день.
- Хостинг — Beget, серверная среда Ubuntu Server Edition и Apache 2.4.63.
- Текущая Joomla создаёт большую и плохо контролируемую нагрузку на хостинг.
- В качестве технического референса рассматривается репозиторий [DimaNikolaevi4/site](https://github.com/DimaNikolaevi4/site).

## Ожидаемый результат

- Готовый статический сайт без необходимости выполнять PHP-код и обращаться к базе данных при каждом просмотре страницы.
- Сохранённая или улучшенная структура меню текущего сайта.
- Все основные страницы и подразделы перенесены без потери контента.
- Быстрая загрузка страниц и минимальная серверная нагрузка.
- Две полноценные темы: светлая и тёмная.
- Корректная работа на компьютерах, планшетах и телефонах.
- Доступный интерфейс, которым можно пользоваться с клавиатуры и вспомогательными технологиями.
- Предсказуемое отображение в современных Chrome, Firefox, Safari и Edge.
- Понятная инструкция для человека и ИИ-агента по созданию новых страниц.

## Основные задачи

### 1. Аудит текущего сайта

- Составить карту всех URL, страниц и подразделов Joomla.
- Определить фактические причины нагрузки: PHP, база данных, расширения, боты, изображения или отдельные URL.
- Выделить страницы, которые нужно перенести в первую очередь.
- Составить таблицу соответствия старых URL новым URL.
- Подготовить резервную копию Joomla до переключения домена.

### 2. Выбор и подготовка технической основы

Предварительный вариант — использовать статический генератор Eleventy и переработать репозиторий-референс:

- Eleventy для сборки HTML.
- Nunjucks для макетов и компонентов.
- Markdown с YAML front matter для контента.
- CSS-переменные для единой дизайн-системы.
- Сборка проекта в папку public/.
- Публикация готовых файлов на Beget.

Это решение не считается окончательным, пока не будут проверены структура шаблона, лицензии сторонних компонентов и требования к будущему ИИ-агенту.

### 3. Создание визуальной системы

- Разработать собственную цветовую палитру, а не оставлять чёрно-белый шаблон.
- Создать отдельные токены для светлой и тёмной темы.
- Определить шрифты, размеры заголовков, интервалы, радиусы, кнопки, карточки и состояния ссылок.
- Сделать визуальный стиль узнаваемым и связанным с автором сайта, обучением и воспитанием.
- Не копировать сторонние шаблоны буквально: использовать их как технический и визуальный референс.
- Согласовать сначала главную страницу и базовые компоненты, затем распространять систему на остальные страницы.

### 4. Реализация светлой и тёмной темы

- Добавить ручное переключение темы.
- Учитывать системную настройку prefers-color-scheme при первом посещении.
- Сохранять выбор пользователя.
- Не делать тёмную тему простой инверсией светлой.
- Проверить контраст текста, ссылок, кнопок, фона, границ и фокуса в обеих темах.
- Не передавать смысл только цветом.

### 5. Адаптивность

- Проектировать сначала для небольших экранов.
- Проверить ширины телефона, планшета, ноутбука и широкого монитора.
- Сделать удобное мобильное меню.
- Не допускать горизонтальной прокрутки.
- Обеспечить удобные размеры интерактивных элементов.
- Проверить таблицы, документы, изображения, длинные заголовки и списки на мобильных экранах.

### 6. Доступность (a11y)

Целевой ориентир — WCAG 2.2 AA.

- Использовать правильную семантику HTML.
- Сделать логичный порядок перехода по клавише Tab.
- Добавить видимые состояния focus-visible.
- Добавить ссылку перехода к основному содержимому.
- Использовать ARIA только там, где нативной семантики недостаточно.
- Добавить альтернативные описания для значимых изображений.
- Проверить заголовки, навигацию, формы, меню и диалоги.
- Учитывать prefers-reduced-motion.
- Проверить работу интерфейса без мыши.
- Проверить контраст в обеих темах.

### 7. Кросс-браузерность

Проверить сайт в актуальных версиях:

- Google Chrome.
- Mozilla Firefox.
- Safari.
- Microsoft Edge.

Также проверить мобильные Safari и Chrome. В дизайне не использовать возможности, для которых нет разумного fallback в поддерживаемых браузерах.

### 8. Контент и ИИ-агент

- Хранить страницы и материалы в понятной структуре каталогов.
- Описать обязательные поля страницы: заголовок, описание, URL, раздел, дата, изображение и текст.
- Создать несколько типов страниц: главная, раздел, подраздел и материал.
- Подготовить файл AGENTS.md с правилами для ИИ-агента.
- Описать шаблоны, допустимые поля, правила URL и требования к доступности.
- Запретить агенту менять дизайн-систему без отдельной задачи.
- Перед публикацией проверять сборку, ссылки, метаданные и структуру страницы.
- Предпочтительный процесс — pull request или предварительный просмотр, а не публикация непроверенного контента напрямую.

### 9. Производительность и SEO

- Отдавать готовые HTML, CSS, JavaScript и изображения без серверного рендера.
- Оптимизировать изображения и использовать современные форматы с fallback.
- Удалить неиспользуемые библиотеки и скрипты.
- Не подключать тяжёлые внешние ресурсы без необходимости.
- Добавить sitemap.xml, robots.txt, canonical URL и корректные метаданные.
- Настроить 301-редиректы со старых Joomla URL.
- Проверить битые ссылки и отсутствующие страницы.
- Сохранить важные адреса материалов, если это возможно.

### 10. Публикация на Beget

- Собирать проект локально или в GitHub Actions.
- Публиковать только готовое содержимое папки public/.
- Не переносить на хостинг node_modules, исходники и служебные файлы GitHub.
- Подготовить безопасный способ публикации по SSH/SFTP после проверки возможностей аккаунта Beget.
- Сохранить возможность быстро вернуться к резервной копии Joomla.
- Не переключать домен до проверки всех URL и редиректов.

## Этапы работы

### Этап 1. Исследование

- Аудит текущего сайта и нагрузки.
- Карта URL и меню.
- Проверка контента и документов.
- Проверка лицензий выбранного шаблона и сторонних компонентов.

### Этап 2. Визуальная концепция

- Палитра светлой темы.
- Палитра тёмной темы.
- Типографика.
- Главная страница.
- Навигация.
- Карточки и типовые блоки.
- Мобильные состояния.

### Этап 3. Базовый шаблон

- Layout сайта.
- Header и footer.
- Главное меню и подменю.
- Переключатель тем.
- Типовые страницы.
- Система контента Markdown.

### Этап 4. Перенос контента

- Перенос страниц из Joomla.
- Перенос документов и изображений.
- Настройка новых и старых URL.
- Проверка заголовков, описаний и ссылок.

### Этап 5. Проверка качества

- Адаптивность.
- Доступность.
- Кросс-браузерность.
- Скорость загрузки.
- Битые ссылки.
- Светлая и тёмная темы.
- Корректность сборки в чистом окружении.

### Этап 6. Публикация

- Сборка production-версии.
- Загрузка статических файлов на Beget.
- Проверка домена и HTTPS.
- Включение 301-редиректов.
- Наблюдение за нагрузкой после переключения.
- Архивирование Joomla до окончательного отключения.

## Критерии готовности

Сайт можно считать готовым к переключению, если:

- все согласованные разделы и подразделы доступны;
- ключевой контент перенесён и проверен;
- сайт работает как статический результат сборки;
- Joomla и база данных не участвуют в обычной выдаче страниц;
- работают светлая и тёмная темы;
- сайт удобен на телефоне, планшете и компьютере;
- основные сценарии проходят с клавиатуры;
- контраст и фокус проверены;
- сайт проверен в Chrome, Firefox, Safari и Edge;
- старые важные URL перенаправляются на новые;
- настроены sitemap.xml и robots.txt;
- есть инструкция для ручного редактирования и ИИ-агента;
- имеется резервный план возврата к текущему сайту.

## Принцип работы над проектом

Сначала согласовываем структуру и визуальную систему, затем реализуем базовый шаблон, после этого переносим контент. Не смешиваем одновременно большой редизайн, миграцию всех материалов и публикацию на домене.

Каждое изменение должно быть проверяемым, обратимым и понятным для следующего человека или ИИ-агента, который будет работать с проектом.
