## 🎯 Принцип

**Тяжёлые медиафайлы (видео, большие PDF/DOCX, большие изображения) НЕ хранятся в Git-репозитории.**
Они лежат на хостинге Beget в изолированной папке и доступны через symlink.

Это:
1. Сохраняет репозиторий лёгким (`.git` сейчас ~181 MB, было 258 MB)
2. Не требует перекачивания больших файлов при каждом `git clone`
3. Позволяет старому сайту на Joomla продолжать работать из `~/bardakov.rf/public_html/`

## 🏗 Архитектура на хостинге Beget

```text
/home/m/mitiba/
├── bardakov.rf/                     # СТАРЫЙ сайт (Joomla). Только для чтения.
│   └── public_html/
│       └── images/Animation/        # Оригиналы видео (остались на месте)
│
└── bardakov.rf-v2/                  # НОВЫЙ проект (Eleventy, поддомен сит.бардаков.рф)
    ├── large-media/                 # 🔒 ИЗОЛИРОВАННОЕ хранилище (вне public доступа)
    │   ├── video/                   # Видеофайлы
    │   ├── documents/               # Тяжелые PDF и DOCX (>5 МБ)
    │   └── images/                  # Тяжелые изображения (>3 МБ)
    │
    └── public_html/
        └── assets/                  # Публичная директория нового сайта
            ├── video ->     /home/m/mitiba/bardakov.rf-v2/large-media/video      (symlink)
            ├── documents -> /home/m/mitiba/bardakov.rf-v2/large-media/documents  (symlink)
            └── images ->    /home/m/mitiba/bardakov.rf-v2/large-media/images      (symlink)
```

**Права доступа:**
- Папки: `755`
- Файлы: `644`

**Проверка доступности:** веб-сервер Nginx отдаёт файлы с `HTTP/2 200 OK`.


## 🆕 Как добавить новый большой файл

### Сценарий 1: ИИ-агент получил новый видео- или PDF-файл

1. **НЕ коммитить файл в репозиторий** — `.gitignore` всё равно его исключит
2. Попросить пользователя загрузить файл на хостинг Beget:
   ```bash
   # По SFTP/SSH на хостинг Beget
   scp "новый_файл.pdf" mitiba@server.beget.com:~/bardakov.rf-v2/large-media/documents/
   ```
3. Добавить запись в `migration-source/large-files-inventory.csv`
4. Использовать в контенте абсолютный URL:
   ```markdown
   [Скачать новый файл (PDF, 8 МБ)](https://сит.бардаков.рф/assets/documents/новый_файл.pdf)
   ```

### Сценарий 2: ИИ-агент верстает страницу, ссылающуюся на существующий большой файл

Использовать **только абсолютные URL** из инвентаря выше. Не пытаться копировать файлы в `src/assets/`.

**Пример для Markdown:**
```markdown
[Скачать Устав СИТ (PDF, 5.2 МБ)](https://сит.бардаков.рф/assets/documents/Устав-ГБПОУ-РО-СИТ-14.12.2018[1].pdf)
```

**Пример для Nunjucks (видео):**
```html
<video controls width="100%" poster="/assets/images/video-poster.webp">
  <source src="https://сит.бардаков.рф/assets/video/Бардаков_самопризентация.mp4" type="video/mp4">
  Ваш браузер не поддерживает видео.
</video>
```

**Пример для кнопки- ссылки:**
```html
<a href="https://сит.бардаков.рф/assets/documents/ПР МДК 03.02 КИП 4 КУРС.docx"
   class="btn btn-primary"
   download>
  <i class="bi bi-download"></i> Скачать практическую работу (DOCX, 14 МБ)
</a>
```

### Сценарий 3: Маленькие файлы (<5 МБ)

Маленькие PDF и изображения оставляем в репозитории как обычно:
```
src/assets/docs/obuchenie/prakticheskaya-rabota-1.pdf
src/assets/images/prakt/kip/1.png
```

Эти файлы коммитятся в Git и попадают в `public/assets/` после сборки Eleventy.

## 📐 Правила определения «тяжёлого» файла

| Тип файла | Порог | Действие |
|---|---:|---|
| Видео (`.mp4`, `.mov`, `.avi`, `.mkv`) | Любой размер | Только на хостинге |
| Архивы (`.zip`, `.rar`, `.7z`) | Любой размер | Только на хостинге |
| PDF (`.pdf`) | >5 МБ | На хостинге |
| DOCX (`.docx`) | >5 МБ | На хостинге |
| Изображения (`.jpg`, `.png`) | >3 МБ | На хостинге (или оптимизировать в WebP) |
| Изображения (`.webp` после оптимизации) | <3 МБ | В репозитории |

## 🔒 Гарантии `.gitignore`

Файл `.gitignore` настроен так, чтобы **гарантированно** исключить тяжёлые файлы из репозитория:

```gitignore
# Тяжелые медиафайлы (хранятся отдельно на хостинге через symlinks)
*.mp4
*.mov
*.avi
*.mkv
*.zip
*.rar
*.7z
large-media/
```

⚠️ **Важно:** Эти правила применяются **глобально** — даже если файл случайно появится в `src/assets/` или в `old/`, он не попадёт в коммит.

---

## 🚫 Что НЕ нужно делать

1. **НЕ коммитить** `.mp4`, `.zip`, `.rar` файлы в репозиторий — `.gitignore` их исключит
2. **НЕ копировать** большие файлы в `src/assets/` — они должны лежать только на хостинге
3. **НЕ использовать** относительные пути для больших файлов — только абсолютные URL с `https://сит.бардаков.рф/`
4. **НЕ удалять** оригиналы из `~/bardakov.rf/public_html/images/` на старом сайте Joomla — они там нужны для работы старого сайта
5. **НЕ менять** структуру `~/bardakov.rf-v2/large-media/{video,documents,images}/` — она зафиксирована в symlink'ах

## 🔧 Технические детали для будущего ИИ-агента

### Как проверить, существует ли файл на хостинге

Через `curl`:
```bash
curl -I "https://сит.бардаков.рф/assets/video/Бардаков_самопризентация.mp4"
# Ожидаемый ответ: HTTP/2 200
```

### Как добавить новую категорию файлов на хостинг

Если понадобится новая категория (например, `audio/`):

1. Попросить пользователя выполнить на хостинге:
   ```bash
   mkdir -p ~/bardakov.rf-v2/large-media/audio
   chmod 755 ~/bardakov.rf-v2/large-media/audio
   ln -s ~/bardakov.rf-v2/large-media/audio ~/bardakov.rf-v2/public_html/assets/audio
   ```
2. Добавить категорию в этот документ
3. Использовать URL вида: `https://сит.бардаков.рф/assets/audio/<имя_файла>`

## ✅ Проверочный чек-лист для ИИ-агента

Перед использованием любого медиафайла в контенте:

- [ ] Файл меньше 5 МБ? → Используем относительный путь, коммитим в репозиторий
- [ ] Файл больше 5 МБ (или видео/архив)? → Используем абсолютный URL с `https://сит.бардаков.рф/`
- [ ] Файл уже есть в `large-files-inventory.csv`? → Используем готовый URL
- [ ] Файл новый? → Просим пользователя загрузить на хостинг, добавляем в inventory
- [ ] Никогда не коммитим `.mp4`, `.zip`, `.rar`, файлы >5 МБ в репозиторий
